## 兑换码前置校验（修复严重缺陷）

用户指出：兑换码必须是 new-api 管理员真实创建的，不是随便造的。

原实现靠「建号 → 核销失败 → 删号回滚」事后补救，mock 下任意字符串都能登录。
改为**前置校验**：`① find_redemption 校验 → ② 建号 → ③ 核销到账`。

关键实现：
- `na.find_redemption(key)`：`GET /api/redemption/` 分页遍历比对 key。
  **不能用 search**——`?keyword=<完整key>` 返回 total=0，keyword 只匹配 name/id。
  页数上限 `BFF_REDEMPTION_MAX_PAGES`（默认 50 × 100）。
- `redeem_code._assert_redeemable`：管理员凭证不可用时**抛 503 拒绝，不放行**。
  宁可让用户等，也不能在校验失效时开闸建号。
- 错误分级：不存在 / 已被使用 / 当前不可用 / 校验失败。
- 状态常量：`REDEMPTION_UNUSED = 1`、`REDEMPTION_USED = 3`。
- mock 层加卡池（`store.create_redemption/find_redemption/use_redemption/
  seed_demo_redemptions`），语义与真实一致；预置卡打 `is_preset` 标记，
  登录页只展示未使用的预置卡，避免测试卡撑长界面。
- 发卡端点 `POST /api/mock/redemption`（仅 mock）。

原回滚逻辑保留为兜底，应对「校验通过后被抢用」的并发。

## 站点动态配置

`GET /api/config` 下发 brand / api / features / demo_codes。
前端 `SITE` 全局对象 + `BRAND()` / `LOGO()` / `APIBASE()` / `MODEL()` 四个取值捷径，
`applyBrand()` 更新 title 与内联 SVG favicon，router 里与 loadPromo 并行加载。

硬编码清零：NexusAPI 9 处、logo「N」4 处、base_url 6 处、模型名 4 处。
`BFF_REDEEM_LOGIN_ENABLED=0` 时兑换码 Tab 消失（事件绑定加 `?.`），后端同步拒绝。

**环境变量名是 `BFF_MOCK_MODE` 不是 `BFF_MOCK`**——传错不报错，静默走真实模式。

换肤实测通过（智算云 / deepseek-chat / 关闭兑换码登录），首页 hero 三行文案、
登录卡、教程页三段代码示例（curl/Python/Node）的 base_url 与 model 全部动态。
