## 教程/文档模块解耦重构（数据驱动多产品）

### 背景
原 `renderDocs` 把「积分」教程硬编码在前端，新增产品要改 JS。目标是支撑 6 种售卖场景
（积分 / Codex / DeepSeek Harness / Token Plan / Coding Plan / Agent Plan）。
用户明确：**无需兼容旧版本**；5 个新产品先用占位档案跑通链路，内容后补。

### 架构
YAML 档案（内容） → `app/docs_catalog.py`（加载 + Pydantic 校验 + 变量插值 + 白名单）
→ `/api/docs`（索引，不含正文）+ `/api/docs/{id}`（正文）→ `static/docs.js`（渲染器注册表）。

段落类型 7 种：`markdown` / `steps` / `platform_tabs` / `pricing_table` / `table` / `callout` / `faq`。
**新增产品只加一份 YAML，前后端零改动。**

### 关键决策
1. **系数表两级回源**（`app/pricing.py`）：内存 TTL 缓存 → 上游 `/api/pricing` → 快照兜底。
   上游失败**绝不 500** —— 文档是售前页，白屏等于卖不出去。但回落时必须标 `stale` +
   `snapshot_date` 并由前端显式提示：无日期的旧价格比没有价格更危险（用户会当成现价）。
2. **换算必须走 `config.quota_to_points`**，不在 docs 模块自算，否则文档页与日志页两套口径。
3. **图标键名校验从 `static/app.js` 反向解析 ICONS 键集**（22 个），不硬编码清单 —— 否则会
   与前端漂移。档案写错图标名会静默回落成 book，故该校验接入 `/readyz`，并配了正负向测试。
4. **`BFF_DOC_PRODUCTS` 留空 = 全部启用**：新增档案不该因忘改环境变量而静默消失；
   白名单里写了不存在的 id 会在 `/readyz` 报错。
5. 详情接口注入定价时**复制 sections 而非改缓存原对象**，否则第二次请求读到被污染的副本。

### 兼容性
昨晚新增的管理员配置页面已确认兼容：前端路由表新增 `#/docs/:id` 两级路由，未触碰 admin 逻辑。

### 验证
112 项测试通过（原 92 + 新增 20）；ruff 本次范围全绿；emoji 门禁扫描 50 个文件 0 违规；
端到端确认 6 个产品详情均 200、未知产品 404、`/readyz` = ready。
**上游 `https://api.aihuobao.cn/api/pricing` 实测 200 可用**，系数表走实时数据而非兜底。

`scripts/refresh_pricing_snapshot.py` 手动刷新快照：对 `urlopen` 显式限定 http(s) scheme

## 清偿 `on_event` 技术债 → lifespan

### 背景
`app/main.py` 用 `@app.on_event("shutdown")` 归还 httpx 连接池。昨天已实测
`starlette 1.6.0` 移除了 `Starlette.on_event`，当前能跑纯粹依赖 FastAPI 兼容层。
兼容层一旦移除，收尾逻辑会**静默失效**：服务照常启动、测试照常通过、连接池慢慢泄漏。
这是零报错的故障类型，所以优先清掉。

### 改动
1. 改用 `@contextlib.asynccontextmanager` 定义 `lifespan`，`FastAPI(lifespan=...)` 传入；
   lifespan 定义必须前置到 `app = FastAPI(...)` 之前。
2. 顺带把原先在 **import 期**执行的启动副作用（启动日志、mock 预置演示卡）移进
   lifespan 启动阶段 —— import 期做副作用本身也不干净。
3. `scripts/` 清掉 5 个 ruff 错误（3 个 autofix，另手改
   `e2e_redeem_login.py` 的 F841 与 `probe_user_update.py` 的 E702 分号）。

### 测试抓到真 bug（值得记）
先写的 `try/finally` 只包住 `yield`，注释却声称覆盖了启动失败场景。
`test_shutdown_closes_client_even_if_startup_fails` 立刻挂掉：异常发生在 `yield`
**之前**，`try` 块尚未进入，`finally` 根本不执行。修正为 **`try` 包住整段启动逻辑**。
教训：`finally` 的覆盖范围取决于 `try` 起始位置，不是 `yield` 位置；这类错误只有
「启动期抛异常」的用例才能抓到，正常路径测试全绿也照样漏。

### 新增测试（`tests/test_health.py`，2 条）
`test_shutdown_closes_http_client`（替身 `na.close`，断言运行期不调用、退出时调用一次）、
`test_shutdown_closes_client_even_if_startup_fails`（启动期抛错也须归还连接池，
否则崩溃重启循环会耗尽上游连接数）。两条都与实现方式解耦，只锁「退出必然 close」这个事实。

### 验证
`ruff check .` 全清，全量 **117 项通过**（115 + 2）。
`tests/conftest.py` 的 client 夹具已用 `with TestClient(...)`，故 lifespan 在所有
现有用例中都真实触发，改动风险面已被既有测试覆盖。

## 修复：整站白页（路由表在字面量求值期引用尚未加载的函数）

用户报「本地启动后白页打不开」。根因是**脚本加载顺序 × const 字面量求值时机**，
不是后端问题 —— 服务端一切正常，接口全部 200。

### 根因
`static/index.html` 先加载 `app.js`（第 13 行）后加载 `docs.js`（第 15 行），
而 `renderDocs` / `renderDocProduct` **只定义在 docs.js**。
`app.js:211` 的 `const routes = { ..., "/docs": renderDocs }` 在**求值该对象字面量时**
就要去取 `renderDocs` 绑定，此时它还不存在 → 抛 `ReferenceError` → **整个 app.js 中断**，
连文件末尾的 `router()` 都没执行 → `#app` 始终为空。

### 修复
`"/docs": renderDocs` 改为 `"/docs": () => renderDocs()`，把取值推迟到路由命中时。
（`#/docs/:id` 那条本来就是箭头函数包裹，所以只有索引页这一处中招。）

### 诊断方法（这类问题的通用套路，值得复用）
浏览器控制台**空的**，极具误导性 —— 因为抛错发生在采集器附着之前。
真正定位靠的是**探测顶层 `const` 的 TDZ 状态**：

    ['ICONS','routes','PUBLIC_PAGES','PROMO'].forEach(n => { try{ eval(n) }catch(e){ /* TDZ */ } })

结果 `ICONS`/`PROMO` = OK，而 `routes`/`PUBLIC_PAGES`/`SECTION_RENDERERS` = ReferenceError，
**已初始化与未初始化的分界线就是抛错行**。要点：
- `typeof router === "function"` 会误导（函数声明会提升，与是否执行完无关）。
- `typeof window[fn]` 现在查全是 function，因为那是**两个文件都加载完之后**的状态，
  不代表 `app.js:211` 求值那一刻的状态。**别用事后快照推断当时时序。**
- `node --check` 通过、把脚本单独 `node` 跑也不报错 —— 纯运行期时序问题，静态检查抓不到。

### 教训
把**跨文件的函数引用**写进模块顶层 `const` 字面量，等于给加载顺序设了一个硬依赖，
且失败形态是「整站白页 + 控制台无输出」。跨文件引用一律用惰性包裹或事后注册表挂载。

也没有教程详情功能，**不受此 bug 影响、无需同步**。`demo/app.js` 已不存在。

## 三个线上报错修复（微信充值 / 只读盘 / 教程页自定义）

### 1. 微信充值 AttributeError: 'str' object has no attribute 'get'
根因：new-api 的 epay 适配返回 `data` 类型不固定 —— 支付宝给对象（表单字段），
**微信支付给字符串**（收银台 URL）。原实现写死 `body["data"].get(...)`，微信必崩。
修法：在 `app/newapi_client.py:423 pay_create` 做归一化，返回
`{mode, url, params, order_no}`，`mode` ∈ {form, redirect}；redirect 分支的订单号用
`_trade_no_from_url`（认 out_trade_no / trade_no 两种命名）从 URL query 抽，抽不到给空串，
上层退回余额比对兜底。`app/main.py:556` 改成消费 `gw["order_no"]`。
前端 `static/app.js:1066 openCashier` 按 `gateway_mode` 分流，且不靠「params 是否为空」
自动判断 —— 空 params 也可能是上游异常，静默跳网关根地址会给用户一个看不懂的错误页。
弹窗被拦时把地址挂到 order 上渲染成可点链接，否则页面只转圈、钱永远付不出去。

### 2. OSError: [Errno 30] Read-only file system: '/app/data'
根因：`config.DATA_DIR` 默认是源码同级 `./data`，容器里即 `/app/data`，而根文件系统
`read_only: true`。compose 已设 `BFF_DATA_DIR: /data`，但 **Dockerfile 缺 ENV 默认值**，
裸跑 `docker run` 仍复现；且四个状态文件里只有 `admin_cred.json` 指了 `/data`，
**`BFF_SETTINGS_FILE` 漏掉** —— 这是「页面保存配置必 500」的直接原因。
修法：Dockerfile ENV 显式声明全部四项（DATA_DIR / PROMO_STATE_FILE /
ADMIN_CRED_FILE / PRICING_SNAPSHOT_FILE / SETTINGS_FILE）。显式路径的价值是
`docker inspect` 一眼可见，运维不必翻代码默认值。
另修错误可读性：`app/settings.py:_save` 原先 `os.makedirs` 在 try **之外**，只读盘上
它是第一个抛错的调用，异常直接冒到路由变成裸 500。现收进 try 并转 `StorageError`，
消息点明「改 BFF_DATA_DIR / BFF_SETTINGS_FILE 指向卷内路径」。

### 3. 教程页为何不能在管理页自定义
非缺陷，是设计边界：教程内容由 `docs/products/*.yml` 驱动，且 `docs/` 是
`COPY` 进镜像的，运行时只读 —— 管理页天然改不动。管理页只能控 `DOC_PRODUCTS`
白名单（哪些产品可见），改不了内容本身。
「上传 HTML」这条路**不建议开**：section 类型走白名单渲染，注入裸 HTML 等于给
管理端开一个存储型 XSS 面（管理员账号被盗即全站挂马）。若确需自定义，
建议走「YAML 挂卷 + 结构化 section」，不引入 raw HTML。

### 验证
`pytest tests/ -q` → 118 passed（新增 `test_readonly_fs_returns_actionable_error`，
mock `settings.os.makedirs` 抛 Errno 30，断言 500 且 message 含 `BFF_DATA_DIR`）。
`dist/` `demo/` 是纯前端 mock 演示产物，Dockerfile 只 `COPY static/`，
应用也只挂 `static/`（`main.py:89 STATIC_DIR`），故 `dist/app.js` 陈旧不影响生产。

## 修复：注册邮箱收不到验证码（BFF 从未真正调上游发信）

用户报「邮箱收不到验证码，new-api 那边验证过能发」。**BFF 侧根本没接这条链路**。

### 根因两层，第二层更严重
1. `POST /api/verification` 是**纯占位实现**：只校验邮箱正则就返回
   「验证码已发送（演示：任意 6 位数字均可）」，**一行上游调用都没有**。
   真实模式下也走这个分支 —— 提示成功但信永远发不出去。
2. 注册走 `admin_create_user` 影子建号（原 `main.py:319`），该接口
   **既不校验验证码、也不写 email 字段**。等于把邮箱验证整条链路旁路掉：
   用户拿到的是邮箱未绑定的账号，日后无法用邮箱找回密码。
   即使修好发信，不修这层仍是「验证码形同虚设」。

### 上游实测契约（v1.0.0-rc.24，api.aihuobao.cn）
- 发信：**`GET /api/verification?email=<addr>&turnstile=`** —— 不是 POST+JSON，
  参数走 query，turnstile 关闭时传空串。验证码存活 10 分钟，状态只在 new-api 侧，
  **BFF 无从校验**，必须交给上游注册端裁决。
- 注册：`POST /api/user/register`，body 需 `username/password/email/verification_code`，
  上游自己校验验证码并绑定邮箱。
- 业务失败一律 **HTTP 200 + success:false**，靠 message 判定。
- 站点开关 `email_verification` 现为 **True**（8-24 记录里是 False，期间已由用户开启），
  SMTP 也已配好 —— 与用户所说一致。

### 改动
- `app/newapi_client.py`：新增 `send_verification()` / `register_user()`，
  docstring 记全上述契约与常见 message。
- `app/main.py`：`/api/verification` 真实模式改调上游（MOCK 保留占位提示）；
  注册改走 `na.register_user` 替代 `admin_create_user`，并前置邮箱正则校验；
  新增 `_mail_error()` 把上游英文 SMTP 报错翻成可操作中文。
- `static/app.js`：删掉「任意 6 位数字均可」误导文案，邮箱/验证码加 `required`，
  发信前本地先过邮箱正则（避免把明显错误地址打到上游触发限流）。

### 错误映射（原文对终端用户无指导意义，必须翻译）
`invalid SMTP account` → 邮件服务未配置，请联系管理员；
`550 ... non-existent account` → 该邮箱地址不存在，请检查后重新输入；
`incorrect or has expired` → 验证码错误或已过期，请重新获取。

### 验证（真实上游，非 mock）
客户端层：真实邮箱发信成功；`nonexistent-zzz-999@qq.com` 被 SMTP 以 550 拒绝
（**证明信确实发出去了，SMTP 通路正常**）；错误验证码注册被上游拒绝。
HTTP 层：格式非法 400「邮箱格式不正确」（本地拦截未打上游）、
不存在邮箱 400 中文提示、错误验证码注册 400「验证码错误或已过期，请重新获取」。

### 踩坑
本地跑真实上游脚本时 **Logfire 出网超时的告警会把 stdout 冲掉**，
表现为「端点没有任何输出」，极易误判成端点崩溃。
加 `LOGFIRE_SEND_TO_LOGFIRE=false` 后结果正常 —— 排查前先关遥测。

### 回归测试 tests/test_register_verification.py（7 项）
此前注册/验证码链路**零测试覆盖**，这是占位实现能长期存活的根因。锁两件事：
真实模式下必须打上游（不得静默假成功）、SMTP 英文错误映射成中文。

写测试时踩的三个坑，下次改 main.py 端点直接复用：
1. **patch 目标是 `main.MOCK`，不是 `config.MOCK_MODE`** ——
   端点读的是模块级常量（`main.py:311`、`main.py:333`），改配置对象无效，
   症状是测试走进意料外分支（当时报「用户名已存在」）。
2. **替身签名必须带 `client_ip=None`** ——
   `send_verification` / `register_user` / `login` 都有这个参数。
3. **`NewApiError` 替身要显式传 400** —— 默认 502 与真实行为不符：
   上游业务失败（HTTP 200 + `success:false`）已在 `newapi_client.py:258` 归一成 400。
   注册成功路径还会调 `na.login` 换 PAT，也得一并替身，否则会打真实上游。

### 顺手修掉的两个真 bug
- `_mail_error` 用 `"exist" in msg` 判用户名重复，
  但 `"expired"` 含 `exist` 子串 → 验证码过期被误报成用户名已存在。改精确匹配。
- 端点 `e.status_code if e.status_code != 502 else 502` 是恒等式（死代码），
  恒返 502，会让前端把「验证码填错」当成网关故障。改为透传 `e.status_code`。
  同一恒等式在 `main.py:741` 还有一处，不属本次范围，**未改，待清理**。
