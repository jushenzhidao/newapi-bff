# 2026-08-26

## 管理员动态配置页面（app/settings.py + /api/admin/settings）

新增运行时配置覆盖层，管理员可在页面上改配置，无需重启进程。

### 改动文件
- `app/settings.py`（新增）：覆盖层。`SPECS` 定义 25 个可配置项 / 6 个分组，每项带
  `(group, label, validator_fn, hint)`。落盘 `data/settings.json`，沿用 `promo.py`
  已验证的原子写模式（`asyncio.Lock` + 临时文件 + `os.replace`）。
- `app/config.py`：原本全是 import 期求值的模块级常量，改为读取时叠加覆盖值。
- `app/main.py`：新增 `GET/PUT /api/admin/settings`、`POST /api/admin/settings/reset`。
- `app/security.py`：会话载荷加入管理员标记，新增 admin 依赖。
- `app/store.py`、`static/app.js`、`static/style.css`：配置页 UI。
- `tests/test_admin_settings.py`（新增）：13 条回归测试。

### 鉴权
用 `BFF_ADMIN_USERNAMES` 环境变量白名单（逗号分隔），不依赖上游 new-api 的 `role` 字段
——避免对上游契约做未验证的假设。`GET` 也要求管理员身份，因为配置项含运营策略。

### 明确排除、不可在线改的键
`BFF_SECRET_KEY`（改了会踢掉所有在线会话）、`NEWAPI_ADMIN_PAT` / `NEWAPI_ADMIN_UID`、
`NEWAPI_BASE_URL`、`COOKIE_SECURE` / `COOKIE_SAMESITE`、`QUOTA_PER_CNY`（new-api 内部
口径，改错会让全站余额算错）。写入被禁键返回 400。

### 已知限制
`data/settings.json` 与 `promo_state.json` 一样**不跨实例共享**。多副本部署时改配置只在
单个 Pod 生效，需要改用 Redis。

## 本项目环境约定（重要，容易踩）
- 所有环境变量都是 `BFF_` 前缀：`BFF_MOCK_MODE=1`（不是 `NEWAPI_MOCK`）、
  `BFF_COOKIE_SECURE=0`、`BFF_SECRET_KEY`、`BFF_SKIP_DOTENV=1`。
  参见 `tests/conftest.py` —— 这些必须在 `import app.main` **之前**设好，
  在测试函数里 `monkeypatch.setenv` 无效。
- 健康检查端点是 `/healthz` 和 `/readyz`，**不是** `/api/health`。
- 配置文件路径在 `app/settings.py:50` 硬编码为 `data/settings.json`，没有对应的环境变量。
  本地冒烟测试会污染真实的 `data/settings.json`，跑完记得 `rm`（该文件已被 gitignore，
  `.gitignore:13` 的 `data/` 覆盖了它）。

## 踩过的坑
- zsh 下 `ENVS="A=1 B=2"; env $ENVS cmd` 不会做单词分割，环境变量根本传不进去，
  表现为莫名的 401。要用内联写法 `A=1 B=2 cmd`。
- `ruff check --fix` 会重写文件，导致后续 Edit 报 "File has been modified since read"，
  需要重新 Read 再改。
- `dist/` 和 `demo/` 是过期的预构建副本，运行时实际服务的是 `static/`，改前端只动 `static/`。

## 验证
92 项测试全过，ruff 无告警。真实 uvicorn 端到端验证：匿名访问 401、管理员登录后
25 项 / 6 组正常返回、改品牌名后 `/api/config` 立即生效、非法值与禁写键均返回 400、
