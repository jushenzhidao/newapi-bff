## 教程/文档模块解耦重构（数据驱动多产品）

### 背景
原 `renderDocs` 把「积分」教程硬编码在前端，新增产品要改 JS。目标是支撑 6 种售卖场景
（积分 / Codex / DeepSeek Harness / Token Plan / Coding Plan / Agent Plan）。
用户明确：**无需兼容旧版本**；5 个新产品先用占位档案跑通链路，内容后补。

### 架构
YAML 档案（内容） → `app/docs_catalog.py`（加载 + Pydantic 校验 + 变量插值 + 白名单）
→ `/api/docs`（索引，不含正文）+ `/api/docs/{id}`（正文）→ `static/docs.js`（渲染器注册表）。

段落类型 7 种：`markdown` / `steps` / `platform_tabs` / `pricing_table` / `table` / `callout` / `faq`。
**新增产品只加一份 YAML，前后端零改动。**

### 关键决策
1. **系数表两级回源**（`app/pricing.py`）：内存 TTL 缓存 → 上游 `/api/pricing` → 快照兜底。
   上游失败**绝不 500** —— 文档是售前页，白屏等于卖不出去。但回落时必须标 `stale` +
   `snapshot_date` 并由前端显式提示：无日期的旧价格比没有价格更危险（用户会当成现价）。
2. **换算必须走 `config.quota_to_points`**，不在 docs 模块自算，否则文档页与日志页两套口径。
3. **图标键名校验从 `static/app.js` 反向解析 ICONS 键集**（22 个），不硬编码清单 —— 否则会
   与前端漂移。档案写错图标名会静默回落成 book，故该校验接入 `/readyz`，并配了正负向测试。
4. **`BFF_DOC_PRODUCTS` 留空 = 全部启用**：新增档案不该因忘改环境变量而静默消失；
   白名单里写了不存在的 id 会在 `/readyz` 报错。
5. 详情接口注入定价时**复制 sections 而非改缓存原对象**，否则第二次请求读到被污染的副本。

### 兼容性
昨晚新增的管理员配置页面已确认兼容：前端路由表新增 `#/docs/:id` 两级路由，未触碰 admin 逻辑。

### 验证
112 项测试通过（原 92 + 新增 20）；ruff 本次范围全绿；emoji 门禁扫描 50 个文件 0 违规；
端到端确认 6 个产品详情均 200、未知产品 404、`/readyz` = ready。
**上游 `https://api.aihuobao.cn/api/pricing` 实测 200 可用**，系数表走实时数据而非兜底。

`scripts/refresh_pricing_snapshot.py` 手动刷新快照：对 `urlopen` 显式限定 http(s) scheme
（防 `NEWAPI_BASE_URL` 被配成 `file://` 读本地文件当上游响应），S310 加 `noqa` 并注明守卫位置；
上游返回空 data 时拒绝覆盖既有快照 —— 空表覆盖有效快照等于亲手销毁兜底数据。

## 修复：改配置后文档缓存不失效（跨模块状态漏洞）

排查「占位档案能否被管理页面配置覆盖」时发现的真实缺陷，非用户报障。

### 问题
`docs_catalog._cache` 与 `pricing._cache` 在**首次加载时完成插值**并长期驻留，
而 `PUT /api/admin/settings` 只写覆盖层、不失效这两个缓存。后果：改品牌名或
积分单位后接口返回「已保存，立即生效」，`/api/config` 确实变了，但 `/api/docs/{id}`
仍是旧文案。**提示成功却没有变化**，是最难排查的一类故障 —— 运营会以为是浏览器缓存。

### 修复（`app/main.py`）
新增 `_DOCS_AFFECTING_KEYS`（7 个）/ `_PRICING_AFFECTING_KEYS`（4 个）两个 frozenset
与 `_invalidate_caches()`，在 `PUT /api/admin/settings` 和 `POST .../reset` 两处
都按变更键集合调用。`POINTS_PER_CNY` 同时属于两个集合（既参与文案插值又参与系数换算）。
宁可多失效一次 —— 重读六份 YAML 的成本可忽略，而缓存不一致的排查成本极高。
补 `from collections.abc import Iterable`。

### 教训：测试断言要挑真实存在的插值点
初版断言用 `{{brand}}` 出现在 `points.yml` 的 sections 里，**失败**。
实际全项目 `{{brand}}` 只出现 1 次且在 YAML **注释**里 —— 该注释明确写了标题刻意
不拼品牌名，避免「Workbuddy积分 积分」这类重复。改用 `{{points_unit}}`（正文出现
14 次，是真实插值路径）后通过。**写断言前先 grep 确认变量真的在目标字段里，
不要凭架构推断。** 各变量出现次数：points_unit 14 / api_base 9 / 其余各 1。

### 新增测试（`tests/test_admin_settings.py`，3 条）
`test_unit_rename_reflows_into_doc_body`（改单位名 → sections 与 title 同步变）、
`test_doc_products_whitelist_takes_effect_at_once`（收窄白名单 → 索引只剩 1 个，
且被排除产品详情页返回 404，不留后门入口）、`test_reset_restores_doc_visibility`
（重置后重新可见）。每条开头显式 `docs_catalog.invalidate()` 隔离用例间缓存串味。

### 验证
全量 **115 项通过**（原 112 + 新增 3）。

### 遗留
`data/settings.json` 不跨实例共享，缓存失效同样只在单 Pod 生效 —— 多副本部署时

## 清偿 `on_event` 技术债 → lifespan

### 背景
`app/main.py` 用 `@app.on_event("shutdown")` 归还 httpx 连接池。昨天已实测
`starlette 1.6.0` 移除了 `Starlette.on_event`，当前能跑纯粹依赖 FastAPI 兼容层。
兼容层一旦移除，收尾逻辑会**静默失效**：服务照常启动、测试照常通过、连接池慢慢泄漏。
这是零报错的故障类型，所以优先清掉。

### 改动
1. 改用 `@contextlib.asynccontextmanager` 定义 `lifespan`，`FastAPI(lifespan=...)` 传入；
   lifespan 定义必须前置到 `app = FastAPI(...)` 之前。
2. 顺带把原先在 **import 期**执行的启动副作用（启动日志、mock 预置演示卡）移进
   lifespan 启动阶段 —— import 期做副作用本身也不干净。
3. `scripts/` 清掉 5 个 ruff 错误（3 个 autofix，另手改
   `e2e_redeem_login.py` 的 F841 与 `probe_user_update.py` 的 E702 分号）。

### 测试抓到真 bug（值得记）
先写的 `try/finally` 只包住 `yield`，注释却声称覆盖了启动失败场景。
`test_shutdown_closes_client_even_if_startup_fails` 立刻挂掉：异常发生在 `yield`
**之前**，`try` 块尚未进入，`finally` 根本不执行。修正为 **`try` 包住整段启动逻辑**。
教训：`finally` 的覆盖范围取决于 `try` 起始位置，不是 `yield` 位置；这类错误只有
「启动期抛异常」的用例才能抓到，正常路径测试全绿也照样漏。

### 新增测试（`tests/test_health.py`，2 条）
`test_shutdown_closes_http_client`（替身 `na.close`，断言运行期不调用、退出时调用一次）、
`test_shutdown_closes_client_even_if_startup_fails`（启动期抛错也须归还连接池，
否则崩溃重启循环会耗尽上游连接数）。两条都与实现方式解耦，只锁「退出必然 close」这个事实。

### 验证
`ruff check .` 全清，全量 **117 项通过**（115 + 2）。
`tests/conftest.py` 的 client 夹具已用 `with TestClient(...)`，故 lifespan 在所有
现有用例中都真实触发，改动风险面已被既有测试覆盖。

## 修复 CI：容器内 `/app/docs/products` 不存在（档案没进镜像）

CI 报 `doc_products_loadable: /app/docs/products 下没有任何有效档案`。
本地 117 项全绿 —— 因为这是**容器打包层**的问题，测试跑在源码树里，天然看不见。

### 根因有两层，第二层才是致命的
1. `Dockerfile` 只 `COPY app/` 与 `static/`，漏了 `docs/`。
2. **`.dockerignore` 用 `*` 全排除 + 白名单模式，白名单里没有 `docs/`。**
   所以即使补了 `COPY docs/ ./docs/`，也会因源路径不在构建上下文内而**直接构建失败**，
   不是拷贝成功。只改 Dockerfile 是修不好的。

### 顺带修掉的隐性缺陷（同类问题，尚未暴露）
`pricing.py` 的 `_SNAPSHOT` 写死 `parent.parent/"data"` → 容器内解析成 `/app/data`，
而状态卷挂在 `/data`，**生产永远读不到快照**。且 `_load_snapshot()` 只 warning 不抛异常，
这个偏差零显性症状 —— 只会在上游挂掉那天发现兜底根本不存在。
改为读 `config.PRICING_SNAPSHOT_FILE`，Dockerfile 加 `ENV BFF_PRICING_SNAPSHOT_FILE=/data/pricing_snapshot.json`
（沿用 `BFF_PROMO_STATE_FILE` / `BFF_ADMIN_CRED_FILE` 惯例，compose 无需重复声明）。

### 改动文件
`.dockerignore`（放行 `docs/`）、`Dockerfile`（COPY docs/ + 新 ENV）、
`app/config.py`（新增 `PRICING_SNAPSHOT_FILE`）、`app/pricing.py`（`_SNAPSHOT` 改走配置）。

### 验证方式（沙箱拉不到基础镜像，docker build 报 auth.docker.io 502）
换两条等效路径验证，未依赖真实构建：
1. 用 `pathspec` 按 dockerignore 语义逐条比对：`docs/products/codex.yml` 进上下文，
   `.env` / `data/promo_state.json` / `dist/app.js` 仍被排除 —— 安全边界没破。
2. 在 `/tmp` 复刻容器目录布局（只放 app/ static/ docs/）后加载模块：
   6 份档案全部可见、`unknown_whitelist_ids()` 为空、快照路径跟随环境变量。
   并用替身把 `_fetch` 打成失败，确认两条降级路径：无快照 → `stale=True` 不抛异常；
   有快照 → `stale=True` 且 `snapshot_date` 原样带出。

### 教训
**`/readyz` 这类"数据文件可加载"检查必须配套改打包清单。**
运行期数据目录（`docs/`）看名字像文档，极易在 Dockerfile 和 .dockerignore 里被当成
可裁剪内容。白名单式 `.dockerignore` 会把"漏加白名单"变成构建失败而非静默缺文件，
算是不错的性质 —— 但前提是有人真的去构建；纯跑 pytest 永远发现不了。

### 沙箱环境记录
`docker build` 拉 `python:3.13-slim` 报 `auth.docker.io: Bad Gateway`，与用户记忆里
"沙箱到 github.com 出网不稳定"是同类问题。本机无法做真实镜像构建验证，
需靠 CI 或改用国内镜像源。另 `git diff` 走分页器会被 SIGKILL（退出码 137），
要加 `--no-pager` 或管道接 `cat`。
