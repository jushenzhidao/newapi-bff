# 2026-10-09

## 🔴 充值实付金额 ≠ 标价：¥10 档扫码出来 ¥73（根因已定位，未修）

**现象**：BFF 充值页选 ¥10 档，跳收银台二维码显示 **¥73.00**（页面按钮写"支付 ¥10"）。

**根因：上游 new-api 的 `Price`（充值价格）默认 7.3，而 BFF 把 amount 当"人民币"用。**

- 上游公式（`controller/topup.go: getPayMoney`）：
  `payMoney = amount × Price × topupGroupRatio × AmountDiscount`
  `Price` 默认 7.3（`setting/operation_setting/payment_setting_old.go: var Price = 7.3`），
  它的语义是 **1 USD = X CNY**（同时被 `channel-billing.go` 用于渠道余额 CNY→USD 换算）。
- 上游 `amount` 的单位由 `quota_display_type` 决定，该实例为 `USD` → amount=10 被理解为 **$10**。
- 于是 10 × 7.3 × 1 × 1 = **73.00**，与二维码完全一致。
- 到账口径：上游给 quota = amount × QuotaPerUnit = 10 × 500000 = 5,000,000，
  BFF 按 `BFF_POINTS_PER_CNY=1000` 折算 = 10,000 积分 → 用户**付 ¥73 拿 10,000 积分**（标称 ¥10）。

**实测证据（匿名可读，零成本复核）**：
`curl -s https://newapi-bff.oneapis.cn/api/status` → `"price":7.3`、`"usd_exchange_rate":7.3`、
`"quota_per_unit":500000`、`"quota_display_type":"USD"`。
对照：`https://api.aihuobao.cn/api/status` 与 `https://aapi.cn/api/status` 的 `price` 都是 **1**
（那两个实例不会出这个问题）；`https://api.oneapis.cn/api/status` 是 RuoYi 后端（401 认证失败），不是 new-api。

**涉及代码**：
- `app/main.py: create_pay_order` → `na.pay_amount()` 拿回 `payable`（=上游 73.00）、`na.pay_create()` 下单；
  `payable` 已在下发数据里，但 `static/app.js` 从不展示（按钮写死 `¥${sel.cny}`）。
- `app/newapi_client.py: pay_amount / pay_create` 都把 BFF 的 CNY 档位**原样**当上游 amount 传。

**修法（待飞哥拍板）**：
- A. 上游 newapi-bff.oneapis.cn 后台把「充值价格 Price」改成 1 → 选 ¥10 就付 ¥10（在线改，不发版）；
  副作用：渠道余额面板的 CNY→USD 换算（/7.3 → /1）与 new-api 原生充值页的应付金额会一起变。
- B. 保留 7.3 语义，BFF 改成按**实付**展示（"应付 ¥73，得 10,000 积分"）。
- C. BFF 下单后加一致性校验：`payable` 与档位金额不符则拒绝下单 + 告警，防上游配置漂移再静默多收钱。

**方法论**：用户侧"实付金额与标价不符"类问题，第一件事是匿名拉上游 `/api/status` 看 `price` /
`usd_exchange_rate` / `quota_display_type` / `quota_per_unit`——四个字段足以还原应付金额公式，不用登录、不烧额度。

## 已落地：BFF 侧「充值叠加上游汇率」开关（默认关闭）

飞哥拍的方案：**BFF 层加开关，不做上游侧改动**。

- `config.py`：新增 `BFF_TOPUP_FOLLOW_UPSTREAM_RATE`（默认 0）。关闭 = 档位金额即应付人民币；
  开启 = 承认上游汇率，按上游算出的真实金额收款。
- `settings.py`：注册进「充值与支付」分组（原「充值档位」改名），并加入 `RATE_SENSITIVE`。
- `newapi_client.py`：`get_upstream_topup_price()`（匿名 `/api/status`，缓存 300s）+
  `reset_upstream_topup_price_cache()`。**读不到一律返回 None，绝不回落成 1.0**。
- `main.py`：
  - 新增 `GET /api/user/pay/preview?amount=` → 下发 `payable / blocked / blocked_reason /
    upstream_price / follow_upstream_rate / points`，前端据此渲染按钮文案；
  - `create_pay_order` 加**金额一致性闸门**：卡在 `pay_amount`（只算金额）与 `pay_create`（建单）
    之间，关闭叠加且上游应付≠档位时 409 拒绝 + 给出修复指引，不留孤儿订单；
  - `_invalidate_caches` 增加 `_PAY_AFFECTING_KEYS` → 保存配置后清汇率缓存。
- `static/app.js`：充值页按下单预览展示"应付金额"、按钮文案用 payable、上游汇率不一致时
  按钮置灰 + 黄色拦截块（`.pay-blocked`）；等待弹窗显示 payable；开启开关时二次确认。
- 文档：`.env.example` / `README.md`（新增「充值金额与上游汇率」小节）/ 两个 compose 加透传。
- 测试：`tests/test_pay_rate_gate.py`（13 例，覆盖拦截/放行/未知/解析失败/mock）。全量 174 例通过。

**实测闭环**：用 `app.newapi_client` 真跑线上上游 → `get_upstream_topup_price()` = 7.3 → ¥10 档应付 ¥73.0，
与二维码金额一致。修好后该站点选 ¥10 会被闸门拦下并提示改上游 Price=1 或打开开关。

**补充结论（余额口径）**：上游额度 = amount × QuotaPerUnit，与 Price 无关。所以 ¥10 档即使 Price=1，
上游仍是 +5,000,000 quota（上游按 USD 展示为 $10，按它自己的 USDExchangeRate 7.3 折账面 ¥73）。
BFF 的报价表（`pricing.py`：美元模型价 × QUOTA_PER_CNY → 积分）本来就是「$1 当 ¥1 卖」的口径，
所以 Price=1 与 BFF 定价自洽；Price=7.3 才是异常。

## 🔁 复查：飞哥「把汇率改成 1」后二维码仍是 ¥73 —— 真相是**改错了字段**

实测 `https://newapi-bff.oneapis.cn/api/status`：

- `"price": 7.3` ← **没动**
- `"usd_exchange_rate": 1` ← **改了**

→ 他改的是 **`USDExchangeRate`**（UI 标签「**人民币兑美元汇率** / CNY per USD」，
位置 **通用设置 → 定价（Pricing）**，`web/src/features/system-settings/general/pricing-section.tsx`）。
该字段**只用于余额/渠道的显示换算，不参与 `getPayMoney`**，所以收款金额纹丝不动。

真正要改的是 **`Price`**：

- UI 标签「**价格（本地货币/美元）**」（i18n key `Price (local currency / USD)`），
  help：「How much to charge for each US dollar of balance (Epay)」
- 位置：**系统设置 → 计费/支付（Billing）→ 支付网关（Payment Gateway）** 分组
  （`web/src/features/system-settings/integrations/payment-settings-section.tsx`，
  section id = `payment`，`build` 里 `Price: settings.Price` → 保存时 `updates.push({key:'Price'})`）
- 源码：`setting/operation_setting/payment_setting_old.go:16 var Price = 7.3`；
  读写 `model/option.go:92 / :507`，option key = `Price`，落 new-api `options` 表

**两个「7.3」必须分清（都会显示 7.3，极易改错）**：

| 字段 | option key | 后台位置 | 作用 |
|---|---|---|---|
| `Price` | `Price` | Billing → Payment Gateway | 进 `getPayMoney`，**决定收款金额** |
| `USDExchangeRate` | `USDExchangeRate` | General → Pricing | 仅显示换算（余额/渠道 $ 折算） |

**副作用提醒**：`USDExchangeRate` 已被改成 1，会让面板里所有美元换算按 1:1 显示（余额、渠道余额），
应改回 7.3（除非确实要改显示口径）。

**零成本复查命令**：`curl -s https://newapi-bff.oneapis.cn/api/status | grep -o '"price":[^,]*'` → 改对后应输出 `"price":1`。
